# 차이코프스키 피아노 협주곡 1번 — 부저 8개 연주

**NUCLEO-F411RE에 올리는 프로그램은 C/어셈블리로 만든 `concert.elf` 또는 `concert.bin`입니다. Python은 보드에서 실행되지 않습니다.**

`ex_code`의 레지스터 직접 제어 방식, 96MHz 클록 설정, CMSIS 헤더, 시작 코드를 바탕으로 만든 별도 프로젝트입니다. 제공된 3개 MIDI를 최대 8개의 동시 음으로 편곡한 데이터가 이미 C 배열에 포함되어 있습니다. 센서·모터 기능은 포함하지 않았습니다.

## 바로 사용하기

1. 아래 표대로 부저 8개의 신호선을 연결하고 GND를 공통으로 연결합니다.
2. STM32CubeProgrammer에서 ST-LINK / SWD로 보드에 연결합니다.
3. 이 폴더의 `concert.elf`를 선택해 Download 및 Verify를 실행하고 보드를 Reset합니다. BIN을 사용할 경우 시작 주소는 `0x08000000`입니다.
4. 파란색 사용자 버튼 B1을 짧게 눌렀다 놓으면 1악장을 시작합니다.

이미 빌드된 ELF/BIN/HEX가 들어 있으므로, 그대로 업로드할 때는 Python과 컴파일러가 필요하지 않습니다. 보드 업로드 자체는 여기서 실행하지 않았습니다.

## 부저 배선

표의 부저 번호는 물리 출력 번호입니다. 연주 중에는 음을 동적으로 배분하므로 특정 부저가 항상 같은 악기나 같은 음을 담당하지 않습니다.

| 부저 | MCU 신호 핀 | 보드 표시 | 헤더 위치 | 전용 PWM | AF |
|---|---|---|---|---|---|
| 1 | PA8 | D7 | CN9-8 | TIM1_CH1 | AF1 |
| 2 | PA0 | A0 | CN8-1 | TIM2_CH1 | AF1 |
| 3 | PB4 | D5 | CN9-6 | TIM3_CH1 | AF2 |
| 4 | PB6 | D10 | CN5-3 | TIM4_CH1 | AF2 |
| 5 | PA1 | A1 | CN8-2 | TIM5_CH2 | AF2 |
| 6 | PA2 | D1 | CN9-2 | TIM9_CH1 | AF3 |
| 7 | PB8 | D15 / SCL | CN5-10 | TIM10_CH1 | AF3 |
| 8 | PB9 | D14 / SDA | CN5-9 | TIM11_CH1 | AF3 |

모든 부저의 GND는 보드 GND와 공통으로 연결합니다. 예를 들어 CN6의 GND 핀을 사용할 수 있습니다. 위 핀에서는 3.3V 논리 레벨의 50% 듀티 PWM을 출력하며, 무음 상태에서는 GPIO LOW로 고정합니다. 2핀 부저의 신호측/접지측 또는 기존 부저 구동 회로의 PWM 입력에 대응시켜 연결합니다. 별도 전원 단자가 있는 모듈이면 해당 모듈의 기존 전원 연결을 사용합니다.

부저의 정격·소비전류는 확인하지 않았으므로, 이 배선표는 **신호 배치**이며 8개 부저의 GPIO 직접 구동에 대한 전기적 적합성을 검증한 것은 아닙니다. 입력 주파수에 따라 음높이가 달라지는 부저를 전제로 합니다.

PA2는 원래 USART2 TX로도 쓰이는 핀입니다. 이 프로젝트에서는 USART2를 초기화하지 않으며, UART 로그도 출력하지 않습니다. PB8/PB9도 PWM 전용으로 사용하므로 I2C와 함께 사용하지 않습니다. SWD 디버깅 핀 PA13/PA14는 유지합니다.

핀 배치는 제공한 데이터시트 48~49쪽의 AF 표와 Nucleo64 회로도 3·5쪽을 대조했습니다.

## 사용자 버튼과 LED

| 조작 | 동작 |
|---|---|
| B1 짧게 눌렀다 놓기 | 재생 시작 / 일시정지 / 이어서 재생 |
| B1 1초 이상 누르기 | 즉시 무음, 다음 악장 선택, 처음부터 재생 대기 |
| 3악장에서 길게 누르기 | 1악장 선택으로 돌아감 |
| 보드 RESET | 1악장 처음부터 대기 |

악장 끝에서는 1.5초 쉬고 다음 악장을 자동 재생합니다. 3악장까지 끝나면 정지합니다. 이때 짧게 누르면 1악장부터 다시 시작합니다. 다음 악장을 직접 선택한 뒤에는 짧게 눌러 재생합니다. 버튼은 30ms 디바운스를 적용했으며, 길게 눌렀다 놓을 때 짧은 누름 동작이 추가로 발생하지 않습니다.

- 초록색 LD2 계속 켜짐: 재생 중.
- LD2 느린 점멸: 일시정지.
- 대기 중 2초마다 1/2/3회 점멸: 선택된 악장 번호.
- 매우 빠른 점멸: 연주 데이터 해독 오류.

1악장 MIDI는 첫 음까지 약 1초의 쉼이 있습니다. 시작 직후 잠깐 무음인 것은 정상입니다.

## MIDI와 편곡 방식

| 악장 | MIDI 길이 | 원본 Note On 수 | 변환 데이터 |
|---|---|---|---|
| 1악장 | 19분 47.778초 | 19,664 | 48,726 bytes |
| 2악장 | 5분 33.942초 | 4,983 | 12,304 bytes |
| 3악장 | 6분 20.133초 | 9,474 | 20,764 bytes |

위 길이는 제공된 MIDI의 종료 시점 기준입니다. 악장 사이 휴식까지 포함하면 전체 자동 재생은 약 31분 45초입니다.

세 파일은 모두 PPQ=480의 Format 1 MIDI입니다. 연주 트랙은 각각 4개이고, 모두 프로그램 번호 0(피아노)으로 되어 있습니다. 관현악 악기별 트랙으로 구분된 원본 오케스트라 MIDI는 아닙니다. 트랙 이름은 `Grand Piano`, `Instrument17`, `Instrument18`, `Instrument19`입니다.

제공된 총보 도입부와 대조해 트랙 1/2를 피아노 중심, 3/4를 반주 중심으로 **추정**하여 배분했습니다. MIDI 자체에 확정적인 악기 구분이 없어 이 역할 구분은 전 구간에 대한 보장이 아닙니다.

편곡은 다음 기준의 자동 축약입니다.

1. 반주 상성부의 최근 선율과 전체 최저음을 우선 확보합니다.
2. 피아노 상성부의 높은 음·낮은 음 및 왼손 성부를 확보합니다.
3. 반주 하성부를 포함하고, 남는 출력에 최근에 친 화음 구성음을 배분합니다.
4. 같은 높이의 중복음은 하나로 합치고, 8음을 넘으면 일부 내성·잔향을 생략합니다.
5. 유지 중인 음은 가능한 한 같은 부저에 남겨 불필요한 재시작을 줄입니다.

원본의 템포 변화, 시작 시각, 건반 유지 시간, 음높이를 사용합니다. 피아노의 페달(CC64)도 읽지만, 사각파 부저에 자연 감쇠가 없으므로 **건반을 놓은 뒤 페달로만 유지되는 시간은 최대 180ms**로 제한합니다. 같은 음을 다시 치는 이벤트도 재출력합니다. 출력 시각은 1ms 단위로 반올림합니다.

부저는 모두 사각파 음색이며 피아노·현악기 음색, 자연 감쇠, MIDI의 음량·팬을 재현하지 않습니다. Velocity는 음 선택 우선순위 일부에 사용되지만 출력 듀티는 50% 고정입니다. 이 결과물은 8음 부저 편곡이며 총보 전체의 모든 음을 그대로 재현한 것은 아닙니다. 매우 낮거나 높은 음의 실제 가청 정도는 부저 특성에 따라 달라집니다. 기본 설정에서는 임의로 옥타브를 바꾸지 않았습니다.

2악장에는 파일 끝까지 페달 등으로 남아 있는 음 40개가 있어 종료 시점에서 정리합니다. 전체 분석, SHA-256, 최대 동시 음 수와 변환 크기는 `generated/analysis.json`에 기록했습니다. 분석의 `max_source_polyphony`/`max_distinct_pitches`는 잔향 180ms 제한 후 수치입니다.

## C 프로그램 구조

| 파일 | 역할 |
|---|---|
| `main.c` | 초기화, SysTick 1ms, B1 디바운스 및 LED |
| `buzzer.c` | 8개 독립 타이머 PWM 및 무음 처리 |
| `player.c` | C 연주 데이터 해독, 음표 일정, 정지·재개·악장 전환 |
| `generated/score_data.c` | 세 악장의 압축 음표 배열, MIDI 음높이별 타이머 값 |
| `clock.c`, `option.h` | 예제 기반 96MHz 설정 |
| `crt0.s`, `rom_0x08000000.lds` | 벡터 테이블, 시작 코드, 512KB Flash / 128KB RAM 배치 |
| `Makefile`, `build.ps1` | ARM GCC 빌드 |
| `midi/` | 사용자가 제공한 MIDI 복사본 |
| `tools/` | PC 전용 MIDI 변환·검증 도구 |

TIM1/2/3/4/5/9/10/11을 부저에 하나씩 할당했습니다. 같은 타이머의 ARR를 공유하는 여러 PWM 채널에 다른 주파수를 억지로 설정하지 않습니다. SysTick만 시간 관리에 사용하고, 음파의 HIGH/LOW 전환은 하드웨어 타이머가 수행합니다. TIM1에는 MOE도 설정합니다.

클록은 HCLK=96MHz, PCLK1=48MHz, APB1 타이머=96MHz, PCLK2 및 APB2 타이머=96MHz입니다. 음별로 PSC/ARR를 계산하여 모든 MIDI 음높이를 지원합니다. 명목 96MHz 기준 타이머 양자화 오차는 최대 약 0.075 cent이며, 실제 음정 오차에는 내부 HSI 클록 오차가 추가됩니다. `clock.c`의 클록을 바꾸면 타이머 표와 SysTick 설정도 함께 수정해야 합니다.

## 다시 빌드하기 — Python 불필요

이 폴더를 작업 디렉터리로 열고 PowerShell에서 실행합니다.

```powershell
.\build.ps1
```

GNU Make를 사용하는 경우:

```powershell
make
```

`Nothing to be done for 'all'`은 산출물이 이미 최신이라는 정상 메시지입니다.
처음부터 다시 빌드하려면 다음을 실행합니다.

```powershell
make clean
make
```

한 번에 실행하려면 `make rebuild`를 사용합니다. `clean`은 펌웨어의
오브젝트 파일과 ELF/BIN/HEX/MAP만 삭제합니다. 소스, MIDI, 변환된 음표 C 배열은 유지합니다.

기본 도구 경로는 예제와 동일합니다.

```text
C:\arm-gnu-toolchain-15.2.rel1-mingw-w64-i686-arm-none-eabi
```

다른 위치라면 다음처럼 지정합니다.

```powershell
.\build.ps1 -ToolDir 'C:\your-toolchain'
make TOOL_DIR=C:/your-toolchain
```

산출물은 `concert.elf`, `concert.bin`, `concert.hex`, `concert.map`입니다. `make run`은 STM32CubeProgrammer CLI가 PATH에 있을 때 연결된 보드에 업로드합니다.

## MIDI를 다시 변환할 때만 — PC에서 Python 사용

이미 변환되어 있으므로 현재 MIDI를 재생하려면 실행할 필요가 없습니다. MIDI 또는 편곡 규칙을 변경할 때만 Python 3로 다음을 실행한 뒤 다시 C 빌드합니다. 외부 Python 패키지는 필요 없습니다.

```powershell
python tools/convert_midi.py
.\build.ps1
```

잔향 제한을 바꾸는 예:

```powershell
python tools/convert_midi.py --sustain-tail-ms 100
.\build.ps1
```

변환 데이터 형식은 `VLQ 시간차(ms) + 변경 부저 비트마스크 + 변경된 음 번호`입니다. 음 번호 0은 무음, 1~128은 MIDI 0~127에 대응합니다. 3개 악장 데이터는 모두 Flash에 보관하며 RAM으로 전체 곡을 복사하지 않습니다.

## 검증 결과와 재현

- ARM GCC 15.2.1, Cortex-M4 hard-float 설정으로 빌드 통과.
- `-Wall -Wextra -Werror` 적용, 컴파일 경고 없음.
- 빌드 시 Flash 약 85KB, 정적 RAM 72 bytes 사용. 정적 RAM 수치에 실행 중 스택은 포함되지 않습니다. 링커에서 최소 4KB 스택 여유를 검사합니다.
- MIDI 템포 변경·running status·페달·같은 음 재타건 테스트 통과.
- 3개 악장의 모든 출력 음이 해당 시각의 원본 유효 음에 속하고 최대 8음 이내임을 검사.
- **보드용 `player.c`를 그대로 PC에서 실행**해 세 악장의 모든 PWM 설정 이벤트와 시각이 변환 데이터와 일치함을 검사.
- 일시정지/재개, 다음 악장 선택, 32비트 밀리초 카운터 wraparound, 전체 자동 재생 종료와 다시 시작 검사 통과.
- BIN의 초기 스택·Reset 벡터·SysTick 벡터와 Flash 크기 확인.

PC의 GCC로 재생 테스트를 빌드한 뒤 Python 검증을 실행할 수 있습니다.

```powershell
gcc -std=c99 -Wall -Wextra -Werror -O2 -I. tools/player_host_test.c player.c generated/score_data.c -o tools/player_host_test.exe
python tools/verify.py
```

실물 보드의 전기적 출력과 부저 소리는 아직 검증하지 않았습니다. 업로드 후 시작·일시정지에서 8개 출력이 함께 꺼지는지, 길게 눌러 악장을 바꿀 수 있는지 확인하세요. 오실로스코프나 로직 분석기가 있다면 재생 중 각 핀에서 서로 다른 주파수가 나오는지도 확인할 수 있습니다.
